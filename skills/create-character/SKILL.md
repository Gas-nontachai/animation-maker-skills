name: create-character
description: Generate a new safe SVG character with separate parts and a schema-valid rig for a single-scene waving animation. Use for new characters requested in natural language or appearance edits to generated parts.
---
The compatible runtime is exactly `@gasnonthachai/animation-maker@1.1.0`, installed in the user's project. Check `node_modules/@gasnonthachai/animation-maker/package.json` and `./node_modules/.bin/animation-maker --version`. If both report 1.1.0, reuse them without reinstalling. On Windows use the `.cmd` shim. Never resolve a developer checkout or a global executable.

If missing or incompatible, check whether `npm view @gasnonthachai/animation-maker@1.1.0 version --fetch-retries=0 --fetch-timeout=10000` confirms availability. A network/permission failure is not evidence of an unpublished package; request host network approval if needed. This version is a release candidate until that registry check succeeds: on E404 report that the maintainer must publish it; do not pretend installation worked or substitute a local tarball. Request permission to run `npm install --save-dev --save-exact @gasnonthachai/animation-maker@1.1.0` when installation is needed and not already authorized. Before the approved npm install, preserve existing package.json fields and merge this scoped security mitigation into its overrides: `"@gasnonthachai/animation-maker": {"zod": "4.6.7"}`. This patches pinned vulnerable transitive Zod copies only within this runtime's subtree. Do not replace unrelated overrides; if that exact scope already has conflicting values, report the conflict for review rather than overwriting it. In a new directory create a minimal private package.json with that override. Preserve the project lockfile and run `npm audit` afterward; do not claim security readiness if unexpected advisories remain. The runtime's root overrides do not propagate to consumers, so this step is required even if an earlier repo audit was clean. Do not run `npx animation-maker` to implicitly fetch code; use the installed shim or `npx --no-install animation-maker`.

For the supported first scenario run `./node_modules/.bin/animation-maker create --project <unused-directory>`. It generates new robot SVGs, a six-part rig and a 3-second wave timeline using the existing schemas. Keep these source files in the user's project. Infer the default friendly robot when no visual description is given; when a description is provided, author or edit the generated SVG primitives to match it while preserving part attachment geometry. No external generation service is needed. The existing waving-character example remains a reference, not the generated character.

Each part has a unique ID, an asset relative to `character/`, nullable parent, position, pivot and global zIndex. Coordinates are SVG units, positive Y down; clockwise rotation is positive. Local matrix is T(position) R(rotation) S(scale) T(-pivot). Parent matrices and opacity propagate. Keep the right-arm pivot/shoulder and its downward default pose when using the wave preset.

SVG viewBox must be `0 0 width height`. Use static svg/g/path/rect/circle/ellipse/line/polyline/polygon primitives and plain presentation attributes. No scripts, CSS, text, images, hrefs, entities or external resources. Asset paths must stay inside the project after symlink resolution. Inspect the installed runtime's `packages/animation-runtime/src/schemas/index.ts` and `scripts/project.ts` for the full contract.

Validate with `./node_modules/.bin/animation-maker validate --project <directory>`. Repair generated source errors at most twice, then report the part/path and stop. Never overwrite unrelated assets or modify the renderer for a character. For a complete animation/export request, follow the animate workflow through doctor, render and inspect, requesting package/browser/render permissions only when needed.
