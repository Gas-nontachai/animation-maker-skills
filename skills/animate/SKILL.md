---
name: animate
description: Create and export a single SVG character or object from natural language, with static or supported transform animation. Handles custom SVG authoring, the default waving robot, local runtime setup, validation and MP4 export, including Thai requests.
---
Complete supported single-asset requests through export. For the existing three-second waving-character prompt, including “สร้างแอนิเมชันตัวละครโบกมือ 3 วินาที และ Export เป็น MP4”, infer a friendly SVG robot, 24 FPS and three waves unless specified. For custom characters or objects, author new geometry to match the prompt using the create-character workflow below. Choose unused project/output paths and preserve generated SVG, rig and timeline files. No Web UI, new animation framework or per-asset renderer changes.

The compatible runtime is `@gasnonthachai/animation-maker@^1.1.1`, installed in the user's project. Check `node_modules/@gasnonthachai/animation-maker/package.json` and `./node_modules/.bin/animation-maker --version`. Both must report the same version satisfying SemVer `^1.1.1` (`>=1.1.1 <2.0.0`, excluding prereleases). Reuse a compatible installation without reinstalling, upgrading, querying npm or changing package.json/package-lock.json. Reject 1.1.0 and 2.0.0; accept 1.1.1, 1.1.2 and 1.2.0. On Windows use the `.cmd` shim. Never resolve a developer checkout or a global executable.

If missing or incompatible, check whether `npm view '@gasnonthachai/animation-maker@^1.1.1' version --fetch-retries=0 --fetch-timeout=10000` confirms availability. A network/permission failure is not evidence of an unpublished package; request host network approval if needed. On E404 report that no compatible runtime is available; do not pretend installation worked or substitute a local tarball. Request permission to run `npm install --save-dev '@gasnonthachai/animation-maker@^1.1.1'` when installation is needed and not already authorized. Before the approved npm install, preserve existing package.json fields and merge this scoped security mitigation into its overrides: `"@gasnonthachai/animation-maker": {"zod": "4.6.7"}`. This patches pinned vulnerable transitive Zod copies only within this runtime's subtree. Do not replace unrelated overrides; if that exact scope already has conflicting values, report the conflict for review rather than overwriting it. In a new directory create a minimal private package.json with that override. Preserve the project lockfile; let npm update it for the approved install, never delete it or force an update of an already compatible runtime. Recheck the manifest/CLI compatibility and run `npm audit` afterward; do not claim security readiness if unexpected advisories remain. The runtime's root overrides do not propagate to consumers, so this step is required even if an earlier repo audit was clean. Do not run `npx animation-maker` to implicitly fetch code; use the installed shim or `npx --no-install animation-maker`.

1. Run `./node_modules/.bin/animation-maker doctor`. Download a browser only if it is missing/incompatible and the user has approved that download: `./node_modules/.bin/animation-maker doctor --download-browser`. The runtime's public Remotion API extracts a compatible project-local headless browser; do not configure system Chrome or request App Management permissions. An explicit user-supplied browser can be passed with `--browser-executable <path>` to doctor and render.
2. Follow the create-character Skill's prompt-first workflow: interpret appearance, choose parts, author safe SVGs with appropriate pivots/parents, then write Rig v1.0 and Timeline v1.0 directly in an exclusively reserved new project directory. Use one part for a static object when appropriate, nested parts for articulated assets, and `tracks: []` when static. Do not create/recolor the default robot for custom requests. Only the default waving robot uses `./node_modules/.bin/animation-maker create --project ./animation`. Read [timeline-spec.md](references/timeline-spec.md) for keyframes. Generate only supported position, rotation, scale and opacity motion; explicitly report unsupported behavior and stop if fulfilling the request requires it. Do not substitute a wave. Do not use an external image-generation service.
3. Run `./node_modules/.bin/animation-maker validate --project ./animation`. Repair errors in the generated sources with at most two correction-and-validation attempts. Never weaken validators, touch runtime code, or loop indefinitely. On persistent errors report the exact part/path and stop rendering.
4. Run `./node_modules/.bin/animation-maker render --project ./animation --output ./output/wave.mp4`. If sandbox binding or browser launch is denied, request approval through the host's supported mechanism for that command, only when needed. Never disable protections. If approval is unavailable or denied, preserve sources and provide that exact render command for an authorized terminal. Describe this as validation-only, not a completed export.
5. Run `./node_modules/.bin/animation-maker inspect --input ./output/wave.mp4`. Check H.264, 1280×720, 24 FPS, 72 frames, duration 3 seconds and no audio. For custom timing derive expected values from timeline.json. Return the MP4 path, source directory and verification result. Do not claim visual movement was checked unless decoded-frame evidence was collected.

A new request is not permission to download packages or browsers silently. Reuse authorization already given in the session rather than asking twice. A successful render and metadata check are distinct from validation-only success. M1 supports one rig in one scene, including non-character objects and nested parts. Supported motion is keyed local transforms and opacity; walking/sitting/typing synthesis, multiple independent objects, interactions, IK, physics, audio and camera motion remain unsupported. Do not promise arbitrary motion synthesis.
